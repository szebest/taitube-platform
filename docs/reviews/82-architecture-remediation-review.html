The through-line

Nearly every defect found is something the repo already forbids in writing.

The rules are unusually good. The enforcement is prose. ARCHITECTURE.md §6 titles itself “Verification & Enforcement” and then lists four git grep commands a human is expected to type. Where a rule is machine-checked, it holds. Where it is written down, it drifts.

Candidates

1. Make the repository seam self-enforcing

Strong local-substitutable
core/repositories/video-repository.ts:105
adapters/postgres/repositories/postgres-video-repository.ts:145
adapters/in-memory/repositories/feed-filter.ts:10
Live defect

The interface declares sort and categoryId. The in-memory adapter implements both. The Postgres adapter destructures { cursor, limit } and silently drops them, ordering unconditionally by createdAt DESC.

In production ?sort=trending returns recency order and ?categoryId=X returns every category — while routes/feed.ts:56 caches per sort+category, storing identical payloads under N distinct Redis keys. Every test passes, because tests run against the double.

Before — two adapters, no conformance
After — one suite, both adapters
Problem Two adapters at one seam drift silently; the double is more capable than production.
Solution One parameterised contract suite executed against every adapter at the seam, with Postgres on PGLite.
Wins
  • The interface becomes the test surface
  • Locality: divergence fails in one place
  • Leverage: one suite, N adapters
  • Closes a live production defect
  • Covers 2,074 untested adapter lines
  • New adapters inherit the suite free

What the frontend actually is

apps/web is a git-subtree import of an unrelated SPA. It talks to https://taitube-backend.onrender.com — a third-party host, not this monorepo’s API. 0 of its 22 endpoints match apps/api. None use the /v1 prefix every real route carries.

The hardcoded host breaks Core Rule 1. The repo’s own local-first grep catches it on the first try — it has simply never been run, because it lives in a manual checklist.

A drift test fails the build when a route and its contract disagree.

Problem The HTTP contract is written twice, in two repos’ worth of code, and the two copies have never agreed.
Solution Author each endpoint’s schema once in @vp/api-contracts; the API derives its route schemas from it and the client derives its fetchers from it.

Scope note. This does not require the React 19 / TanStack rewrite that tickets 49–75 describe. Point the existing app at a configurable local base URL and have it consume the contract package. The rewrite stays a separate decision.

8. Flatten the workspace layout

Speculative in-process
pnpm-workspace.yaml:5-6 · vitest.config.ts:8-9
core/ · adapters/ · observability/ · tests/
Before
packages:
  - 'apps/*'
  - 'packages/*'
  - 'tools/*'
  - 'core'        ← one-off
  - 'adapters'    ← one-off

Two literal entries here force two more in vitest.config.ts. tools/* matches two folders that aren’t packages, so pnpm skips them silently. Root observability/ is config-only and is read by packages/observability’s tests via a repo-root path walk.

After
packages:
  - 'apps/*'
  - 'packages/*'
  - 'tools/*'

core and adapters become ordinary members under packages/. Grafana artifacts move next to the code that validates them. Globs mean one thing everywhere.

Problem Two packages sit at the root for historical reasons, and the inconsistency has already propagated into a second config file.
Solution Move them under packages/ and let the globs do the work.
Why speculative. This is a large, mechanical diff touching every import path for no behaviour change, and SDD §15.1 documents the current layout deliberately. Worth doing only alongside candidate 3, which has to touch package configs anyway. On its own the churn outweighs the gain.
Top recommendation

Start with candidate 1 — make the repository seam self-enforcing

It is the only candidate that closes a defect users can see today: the public feed ignores sort and categoryId in production while every test passes. That gap exists because the seam has two adapters and no shared test, which is precisely the condition a contract suite removes.

It also pays for itself twice. The suite covers the 2,074 untested lines in s3, redis and bullmq, and it establishes the pattern candidate 4 then enforces everywhere else. Candidates 3 and 6 are near-free cleanups that can ride along in the same change.
